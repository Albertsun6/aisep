## ADR-034 · 2026-11-27 · 一个 ADR 一个文件

- **状态**：已采纳（Albert 2026-11-27 拍板，拍板记录第 30 条：改做把 `docs/decisions.md` 拆成一个 ADR 一个文件，即批量合并设计提案 Q2；ADR-033 第 8 款指向本条。下列目录、命名与编号细则是该设计的落实，按第 27 条经 agent 双路评审合入、合并后汇总告知 Albert）。补充 ADR-019 第 1 款与 ADR-033 第 3 款的适用对象，两者原文不改。
- **背景**：ADR 原来都写在 `docs/decisions.md` 一个文件里，并行 PR 各自新增或补记 ADR 时都改同一个文件的末尾，这是合并时最常见的冲突来源（批量合并设计提案第 1 节：第二批 8 次合并里有 3 次在这个文件上冲突）。
- **决策**：
  1. **目录与命名。** 每个 ADR 一个文件：`docs/adr/NNN-<slug>.md`。`NNN` 是三位补零的编号，与 `ADR-NNN` 一致；`<slug>` 是小写英文、数字和连字符组成的短名，只为看文件名时好认，改不改都不影响编号。文件内容从 `## ADR-NNN · 日期[ · 标题]` 这一行开始。
  2. **`docs/decisions.md` 改为索引。** 只放一张表：编号（链接到文件）、日期、标题、状态，按编号升序，一个 ADR 一行。ADR 正文、补记都不写在索引里。索引里的标题是给人扫读用的短名；ADR-030 起标题也写在文件首行，以首行为准。
  3. **补记写在各自文件里。** 对已有 ADR 的补记（如 ADR-022 的「补记（Albert 2026-11-27 定）」）追加在该 ADR 文件的末尾，带日期，原文不改；状态变了时同步改索引里那一行的状态。
  4. **编号分配。** 新 ADR 取 `origin/main` 上 `docs/adr/` 已有最大编号加 1，在同一个 PR 里同时新增文件和索引表末尾的一行。编号一旦合入 `main` 就不再改，也不复用（ADR 被废止时改状态，不删文件）。
  5. **防抢号与冲突处理。** 两个并行 PR 取到同一个编号时，它们新增的文件名一般不同（slug 不同），git 不会报冲突；能报冲突的是索引：两个 PR 都在表的同一位置（末行之后）插入一行，合并时一定是文本冲突。所以：
     - 新增 ADR 的 PR 按 ADR-033 第 6 款属于「有文本冲突」的情形，合并前必须先 `git merge origin/main`，不能走「不更新分支」。
     - 冲突时**后合并的 PR 改号**：取当时 `origin/main` 的最大编号加 1，重命名文件、改文件首行的编号、改索引那一行，并把本 PR 里引用这个新 ADR 的地方一并改掉。已合入的那一个不动。
     - 兜底：`aisep-mcp/tests/test_adr_index.py` 检查索引与 `docs/adr/` 下的文件一一对应、编号唯一、文件首行编号与文件名一致；漏网的重号在 PR 或 push 到 `main` 的 CI 上变红。
  6. **评审分级不因拆分放宽。** ADR-019 第 1 款白名单排除 `docs/decisions.md`，它原来覆盖全部 ADR 正文；拆分后排除项扩到 `docs/adr/**`（任意层级，不区分大小写），即改到任何 ADR 文件或索引的 PR 仍按合并前评审走。ADR-033 第 3 款「`docs/decisions.md` 的 ADR」同样指 `docs/adr/` 下的文件与索引。
  7. **引用写法。** 新写的引用指向具体文件（`docs/adr/NNN-<slug>.md`）或直接写 `ADR-NNN`；不再写 `docs/decisions.md:行号`，行号随补记变动，文件路径加编号不变。已有 ADR 正文里提到 `docs/decisions.md` 的地方属于原文，不改，读作「索引」。`docs/history/` 下的历史材料不改。
- **理由**：
  - 一 ADR 一文件让并行 PR 补记不同 ADR 时改的是不同文件，不再冲突；新增 ADR 只在索引末行留一个刻意保留的冲突点，用来暴露抢号，冲突本身一行就能解决。
  - **参考对象与差别**（链接于 2026-11-27 核实可访问）：
    - adr-tools（[仓库](https://github.com/npryce/adr-tools)）：目录 `doc/adr/`，文件名 `NNNN-title-with-dashes.md`，`adr new` 取目录里最大编号加 1（[`src/adr-new`](https://github.com/npryce/adr-tools/blob/master/src/adr-new)）。借它的目录、文件名形状与「最大号加 1」；差别是编号用三位，因为仓库里已有三百多处 `ADR-NNN` 三位写法，改四位只会制造不一致；adr-tools 不处理并行分支抢号，本条用索引末行的文本冲突加测试兜底。
    - MADR（[文档](https://adr.github.io/madr/)、[仓库](https://github.com/adr/madr)）：目录 `docs/decisions/`，文件名 `NNNN-title-with-dashes.md`，状态写在文件里。借「一 ADR 一文件、状态随文件走」；目录名取 adr-tools 的 `adr`，因为 `docs/decisions.md` 要留作索引，`docs/decisions/` 与它同名易混；不改用 MADR 模板，已有 ADR 原样搬迁，格式沿用本仓库的「状态、决策、理由、后果」。
    - 考虑过、没选：文件名用日期加主题、编号合并时才定（log4brains 的做法）——仓库里大量引用靠 `ADR-NNN`，合并时才定号会让 PR 里写不出自己的编号；文件名不带 slug（`ADR-034.md`）——抢号时会成 add/add 冲突，但与上游惯例不一致，且索引末行已能暴露抢号。
- **后果**：
  - `docs/decisions.md` 的 ADR-001 到 ADR-033 逐个搬到 `docs/adr/`，正文逐字不变，唯一的机械改动是相对链接多一层目录（`](specs/…` → `](../specs/…`），否则链接会断；拆分 PR 里附逐字比对脚本的结果。
  - `AGENTS.md`：文档清单、白名单排除项（加 `docs/adr/**`）、自动合并范围里的「ADR」、已拍板决策一句同步改；仓库里指向 `docs/decisions.md` 某条 ADR 的引用改为指向具体文件（ADR 原文、`docs/history/`、`vendor/`、模型文件里的引用不改）。
  - **风险**：① 抢号若恰好在两个 PR 都不更新分支时合入，会在 `main` 上留下重号：第 5 款要求新增 ADR 的 PR 必须更新分支，测试在 push CI 上兜底，发现即由后合入者改号。② 外部文档里写的 `docs/decisions.md:行号` 失效：仓库内已无此写法，仓库外的交接材料按编号查索引即可。
